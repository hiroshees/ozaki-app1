# 実装計画（ロードマップ）

このファイルは「どの順番で作るか」の地図です。作業の中身・受け入れ条件・進捗は GitHub Issue で管理します。

- 何を作るか → `docs/SPEC.md`
- どの順番で作るか → このファイル
- 1つの作業の中身と進捗 → GitHub Issue（完了状態は Issue の Open / Closed だけで判断する）

## 運用ルール
- 1 Issue = 1 ブランチ = 1 PR。1つの PR で1日以内に終わる大きさにする
- 各 Issue には `phase-N` ラベルを付ける。フェーズの進捗は `gh issue list --label phase-N --state all` で確認する
- Issue を作ったら、下の一覧の `#?` を実際の番号に置き換える
- このファイルには作業の詳細や完了チェックを書かない（Issue と二重管理にしない）
- 計画を変えたら、末尾の「変更履歴」に日付と理由を1行で残す

## 作業の流れ（1 Issue ごと）
1. `/plan Issue #N を実装する計画を立てて` で計画し、内容を確認して承認する
2. ブランチ `issue-N-<短い説明>` を作って実装し、lint・型チェック・テストを通す
3. 本文に `Closes #N` と確認手順を書いて PR を作る
4. `@code-reviewer` でレビューし、人間が確認してマージする（マージは人間が行う）
